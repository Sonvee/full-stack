## 背景与问题

当前管理端登录页尚未接入登录服务，后端尚无账号、角色或权限模块。系统需要建立后台操作人员的账号管理和授权能力，设计可参考若依，但具体功能范围仍需逐项确认。

## 数据与外部约束

- 当前前端管理路由为静态配置，登录页是占位实现，表单使用邮箱和密码；本次确认采用用户名和密码登录，表单需相应调整。
- 当前后端使用 Fastify、Drizzle ORM 与 PostgreSQL；现有数据库 schema 包含字典及测试样例，尚无账号授权实体。
- 账号以生成的唯一 ID 为主键；用户名是必填登录名，创建后不可修改，逻辑删除后允许复用；昵称、邮箱、手机号、备注选填。
- 密码不得明文存储，采用不可逆密码哈希；具体算法与参数待确认。登录采用 Redis 服务端会话，浏览器通过 Cookie 携带会话标识；账号停用或管理员重置密码时立即撤销该账号所有有效会话；角色或角色权限变更后，变更后的有效权限立即对已有会话生效。会话闲置 3 天过期、最长连续有效 7 天；Cookie 安全属性待确认。权限数据来源待确认。
