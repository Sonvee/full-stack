- 最后确认范围：最小可用的全栈管理底座，按单组织独立部署，使用唯一用户名和本地密码登录，通过受控初始化命令建立首个管理员；登录状态可跨浏览器重启保持；管理员维护普通用户、自定义角色；日志首版仅提供后端记录与存储能力，不含前端页面；用户可分配多个角色，权限采用角色授权并集，暂不含数据范围。

## 2. 背景与问题

用户已通过此前讨论形成通用全栈管理系统的长期构思，希望先建设基础框架，为后续管理功能及插件能力提供承载基础。

`architecture.md` 是讨论草案，其中明确标为已确认的长期方向继续作为背景约束；建议方案和待确认事项不自动成为本阶段需求。

### 已检查的项目事实

- 前端采用 Vue 3、TypeScript、Vue Router、Pinia、Tailwind CSS 和 shadcn-vue；目前是欢迎页、关于页及默认放行的路由守卫。
- 后端采用 Fastify，已有 PostgreSQL / Drizzle 和 Redis 的连接配置，目前仅注册健康检查接口，数据库 schema 尚无业务表。
- 尚未实现登录、用户与角色管理、后台布局或插件运行能力。
- 项目已有 pnpm workspace 和 Docker Compose 配置；本次讨论不重新选择现有技术栈。
- 当前没有其他 PRD、ADR 或 Spec 可供复用。

## 3. 目标与非目标

### 已确认目标

- G-01：优先建设最基础的整体管理系统框架，分阶段推进长期构思。
- G-02：先完成需求和技术文档确认，再等待后续明确开发授权。

### 范围状态

首阶段范围已确认包含后台布局与导航、真实登录/退出、用户管理、角色与基础权限、统一请求和异常处理，以及后端登录日志与操作日志的记录和存储。插件能力与日志前端页面后续建设，不进入本阶段。上述功能的未决业务规则仍需逐项确认。

当前推进安排（2026-11-08）：本轮讨论暂停在前台布局与导航，用户先自行搭建布局，完成后再继续需求讨论。此前已确认的需求保留；恢复时先检查实际布局，再衔接其余需求和技术规格。

## 4. 用户与场景

- 部署者：通过受控初始化命令创建首个管理员。
- 超级管理员及获得相应权限的管理人员：维护用户和自定义角色，配置授权。
- 普通用户：使用用户名和密码登录，根据角色授权访问菜单、页面和具体操作。

## 5. 功能需求

以下为已确认需求，尚未确定的详细行为不视为默认授权。

| 编号 | 功能 | 已确认行为 |
| --- | --- | --- |
| FR-01 | 管理界面 | 提供后台布局与导航；菜单和权限点由代码定义，菜单按当前用户权限过滤，首版不提供菜单管理页面 |
| FR-02 | 登录与退出 | 使用唯一用户名和本地密码登录；允许多个设备或浏览器同时登录，各会话独立，退出仅影响当前会话；登录状态跨浏览器重启保持 |
| FR-03 | 会话过期 | 闲置 7 天过期；有效使用可续延闲置期限，但单次登录最长 30 天，达到任一时限均需重新登录 |
| FR-04 | 用户管理 | 管理员创建、编辑、启用/停用账号，分配角色及重置密码；创建或重置密码后不强制用户改密，可直接进入已授权的后台页面；不开放注册或邮件邀请 |
| FR-05 | 角色与权限 | 提供不可删除的超级管理员角色及自定义角色；管理员在角色页面分配代码中已定义的权限；用户可有多个角色，权限取并集；前端控制菜单/页面和操作入口，后端强制校验操作权限 |
| FR-06 | 日志数据能力 | 后端记录与存储登录成功/失败及账号、角色、权限变更事件，区分登录日志与操作日志；不提供前端日志页面 |
| FR-07 | 请求与异常 | 提供统一请求和异常处理能力 |
| FR-08 | 管理变更生效 | 停用账号或重置密码使该账号的全部会话失效；用户角色分配或角色权限调整后，下一次请求按新权限校验，无需重新登录 |

## 7. 数据与外部约束

- 已确认：沿用现有 Vue + TypeScript 前端及 Node.js / Fastify 后端技术方向。
- 待确认：业务数据模型、管理接口契约和具体权限清单。
- 已确认：浏览器认证使用 `@fastify/session` 与 Redis 服务端会话，登录 Cookie 跨浏览器重启保持，详见 [ADR-01](../adr/01-session-authentication.md)；闲置 7 天过期，单次登录最长 30 天。
- 已确认：每个组织独立部署一套系统，本阶段不建设多租户隔离。
- 已确认：通过受控初始化命令建立首个管理员账号；公开注册不是首个管理员的创建途径。
- 已确认：角色权限控制菜单/页面与具体操作，前端据此展示入口，后端强制校验受保护操作；首版不实现业务数据范围权限。
- 已确认：首版采用本地账号密码身份，不依赖外部身份服务。
- 已确认：普通账号由管理员创建和维护，可编辑、启用/停用、分配角色及重置密码；不开放自助注册，不依赖邮件服务。
- 已确认：管理员创建账号或重置密码后，用户可以直接使用管理员设置的密码登录并进入已授权页面，不设置强制改密流程。
- 已确认：系统提供不可删除的内置超级管理员角色，并允许管理员创建自定义角色、配置已定义的菜单和操作权限。
- 已确认：用户可分配多个角色，用户权限为其所有角色授权的并集。
- 已确认：本地账号使用唯一用户名作为登录标识。
- 已确认：关闭并重新打开浏览器不会直接使会话失效；仍按闲置 7 天及单次登录最长 30 天的规则判断登录是否有效。
- 已确认：同一账号可在多个设备或浏览器同时登录，新登录不使其他会话失效；用户退出登录仅撤销当前会话。
- 已确认：停用账号或重置密码使该账号全部会话失效；调整用户角色或角色权限不强制下线，下一次请求按新权限校验。
- 已确认：首版提供后端登录日志和操作日志记录与存储能力；登录日志记录成功/失败事件，操作日志记录用户、角色和权限变更；本阶段不提供日志前端页面。
- 已确认：菜单和权限点由代码定义，管理员通过角色页面分配权限，系统按当前用户权限过滤菜单；本阶段不提供菜单管理页面。
- 长期已确认方向：前后端插件独立开发、构建和安装，安装与升级不要求重建宿主或重启后端主服务；插件能力不在本阶段实现。

## 8. 验收标准

以下条件对应已确认行为，其余详细验收条件随需求对齐补充。

- AC-01（FR-02、FR-03）：有效会话在关闭并重新打开浏览器后仍可使用，不因浏览器关闭而强制重新登录。
- AC-02（FR-03）：会话闲置达到 7 天后失效；持续有效使用可以延长闲置期限，但从本次登录起达到 30 天时仍须重新登录。
- AC-03（FR-05）：用户拥有多个角色时可以使用各角色授权的并集；无操作权限时后端拒绝对应操作。
- AC-04（FR-06）：登录成功/失败以及账号、角色和权限变更有对应的后端日志记录，不要求前端日志查询页面。
- AC-05（FR-02）：同一账号在两个独立浏览器登录后均可使用；其中一个退出后，另一个会话仍可正常使用。
- AC-06（FR-04）：新建普通账号或重置密码后，用户用管理员设置的密码登录，可直接进入已授权页面，不被强制跳转至改密流程。
- AC-07（FR-08）：账号在两个独立浏览器登录后，停用该账号或重置密码，两个旧会话的后续受保护请求均被拒绝；重新启用账号不恢复旧会话。角色授权被撤销后，已有会话的下一次相应操作被拒绝，无需等待用户重新登录。
- AC-08（FR-01、FR-05）：管理员可在角色页面分配代码中定义的权限；用户登录后仅看到其有权访问的菜单，直接访问无权页面或调用受保护接口也不能绕过授权；首版不包含菜单管理页面。
